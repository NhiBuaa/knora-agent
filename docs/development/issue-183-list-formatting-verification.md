## Diagnosis before editing

The observed count-only answer was generated by Cloudflare Workers AI
`@cf/openai/gpt-oss-20b`, using `cloudflare-gpt-oss-cited-answer-v4`. Its stored
generation trace and conversation result contained the same answer: a bold count
followed by seven comma-separated chapter names, with zero newlines. The trace
passed citation validation. The matching browser DOM contained the bold count,
zero list items and one citation chip; selecting it opened the matching source.

The provider returns the decoded answer string unchanged. Validation, persistence,
HTTP projection and the frontend BFF preserve that string. AnswerContent already
supports Markdown lists. The missing structure was present in the generated
payload before display; this diagnosis does not infer a renderer bug from a
screenshot. Prompt v4 only requested lists "when appropriate".

## Approved change

Cloudflare prompt v5 requires separate Markdown bullet lines for an enumeration
of two or more items. When evidence identifies the members of a collection, a
count question receives an introduction with the count and unit in bold, followed
by those members, even without an explicit request to list them. Item meaning and
source order must be preserved; unsupported members must not be invented. Short
answers without an enumeration remain prose.

The instructions contain no chapter count, chapter titles or question-specific
match. Other providers retain their existing prompt. Schema, alias mapping,
validation, refusal, authorization, Markdown renderer, citation selection,
conversation pagination/scroll behavior and historical answers/excerpts are
unchanged. No dependency or output reconstruction is added.
